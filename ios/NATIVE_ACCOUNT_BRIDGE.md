# iOS isolated native account source (inactive)

This source implements the narrow native bridge in `docs/NATIVE_ACCOUNT_BRIDGE.md` against the inspected Capacitor **8.5.3** APIs. It does not enable native Account/CloudClient, configure a service, change permissions, or claim iOS acceptance. `NativeAccountPolicy.endpoint` is nil and the independent `allowedEndpoints` set is empty. No capability/context operation creates a URLSession or probes a server.

## Boundary and packaging

`FitFlowBridgeViewController` is wired into both SceneDelegate and Main.storyboard. Its `capacitorDidLoad` hook installs the `FitflowNativeAccounts` WKScriptMessageHandlerWithReply before Capacitor's initial load. Each call captures its own WK reply handler. Account operations are not CAPPluginCall methods and their results never enter Capacitor's plugin result logging/evaluation path.

Native checks cover WebView and frame WebView identity, main-frame status, exact security origin, frame request URL, current native URL, foreground scene/application, loading state, navigation-delegate identity and packaged root. Account work additionally requires exact `/account` with no query or fragment. Native URL KVO observes History API changes; loading/navigation/renderer callbacks and scene/application notifications revoke context. Every private delivery repeats the checks after background codec work. Foreground does not restore credentials or a context.

Origin checks alone would be insufficient: inspected CapacitorBridge.setServerBasePath changes config.appLocation and WebViewAssetHandler's Router.basePath. The custom Router seals the original Bundle public root at the initial setter. Any later setter permanently poisons account support, including setting the same root or switching away and back, and can never change routed bytes. Current config.appLocation is also checked on every sensitive boundary. instanceDescriptor deliberately avoids the superclass persisted NoCloud-root restoration. Files escaping the bundle route are rejected. A wrapper around the installed capacitor scheme handler blocks special file/proxy paths for ALL resource loads, including scripts that do not invoke navigation delegates. Subframe documents are disallowed (the app does not use them), and special paths are blocked before navigation forwarding. This prevents an alternate same-origin child document from calling parent code to impersonate main-frame provenance. The generated CapApp-SPM package and web assets are unchanged.

The asset guard is registered once on a fresh WKWebViewConfiguration during the pre-construction hook, preserving the public preferences/content controller/data store/process pool/media/navigation settings configured by inspected Capacitor8.5.3. The configuration object is not copied, since a copy carries existing scheme registrations. WebKit rejects duplicate scheme registration even when passed nil; the source must not try to clear-and-replace a registration. See the [WebKit setter implementation](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/Cocoa/WKWebViewConfiguration.mm). Re-review this explicit setting transfer on Capacitor/SDK upgrades. Real WKWebView construction remains an unrun platform test.

## Wire and lifetime

The JSON-string wrapper has exactly version/callId/operation/payload; success has version/callId/ok/value and failure version/callId/ok/error. Invalid or untrusted input with no usable canonical call ID rejects the WK Promise using a fixed local code rather than inventing correlation. Valid decoded calls use the exact JSON-string wrapper. The eight local codes are a closed enum. No remote message, exception text, headers or cookies are returned.

Main owns generation/context/account/bearer/CSRF and pending calls. Ledgers never evict used contexts (4096 per owner lifetime) or request IDs (4096 per context). They fail closed at exhaustion. A small local clear is admitted even when two network/codec operations occupy ordinary slots. Matching clear/background/navigation advances fences before cancellation. Login, logout, account deletion and verification/reset confirmation are dispatch barriers: older work is cancelled and previous owner credentials are cleared before dispatch. Explicit authenticated logout/delete may carry the captured old credentials only inside their private task. A second successful login rotates generation even for the same account.

Raw native login envelopes are parsed only in native code. Exact `{session,nativeToken}`, canonical 32-byte/43-character base64url bearer and SHA-256 `fitflow-csrf-v1:` CSRF binding are checked before installation. JavaScript receives only the sanitized CloudSession. Session reads must match account, native CSRF and exact original server expiry. No refresh occurs. Eight-hour absolute and thirty-minute idle expiry use monotonic deadlines plus the server wall expiry. The per-call twenty-second watchdog includes large incoming decode time and final serialization; late results are fenced.

Only an explicit correlated logout204 confirms server logout. Local clear, timeout, background, loss of a login response or process exit do not prove server revocation. Source drops native references, buffers, stream bodies, handlers and tasks on terminal paths. It does not claim guaranteed erasure of Swift strings or Foundation/WebKit/URLSession internal copies. Foundation parsing already in progress cannot be forcibly interrupted; bounded codec slots remain charged across cancellation until the worker releases its captures, and cancelled output cannot be installed or emitted.

## Transport and resource bounds

Each operation uses its own ephemeral URLSession with nil cookie/credential/cache storage, cookie acceptance disabled, no wait-for-connectivity, a fixed native endpoint plus independent allowlist, exact final-recipient checks, ordinary server-trust evaluation, no other credential challenges, no redirect following and no cache proposals. Responses stream through URLSessionDataDelegate; wire byte caps apply before accumulation. Identity encoding is requested and other content encodings are rejected. No shared session, Capacitor HTTP/cookie helper, download file or whole-body completion API is used.

Token-aware UTF-8/syntax preflight limits ordinary values to bytes, depth32, one million JSON value nodes, duplicate/escaped-alias keys and negative zero before JSONSerialization. Only the dedicated outer wrapper receives one additional depth and four additional value nodes; its nested port and body are rechecked at the original limits. Boolean/number distinction and finite numbers are validated after parsing too. Large incoming sync commands, response parsing and response serialization run off main; immutable captures and cancellation tickets are checked across queue boundaries, then the authoritative generation/frame/root/route guard runs on main. At most two codec jobs remain queued/running even across cancellation generations.

There is no application retry. Mutation upload bodies are handed to uploadTask(withStreamedRequest:) once via needNewBodyStream; a second stream request is rejected and cancelled. Apple documents that this delegate callback supplies the *initial* stream too; setting httpBodyStream alone would be ignored by that API. No replacement stream or authentication credential is provided.

**Remaining platform gate:** URLSession may internally retransmit idempotent requests. The one-shot body policy is a mitigation, not proof that CFNetwork never retransmits any bytes already buffered, nor proof of zero implicit GET retries. Instrumented Apple-platform tests must verify mutation behavior under connection loss/recoverable errors and document the transport's actual guarantee before activation. Never retry an uncertain write blindly; inspect existing CAS/idempotency state. References: [streamed upload API](https://developer.apple.com/documentation/foundation/urlsession/uploadtask(withstreamedrequest:)), [body-stream delegate](https://developer.apple.com/documentation/foundation/urlsessiontaskdelegate/urlsession(_:task:neednewbodystream:)), [Apple QA1941](https://developer.apple.com/library/archive/qa/qa1941/_index.html).

## Verification and remaining gates

Linux source verification: `node ios/Tests/source-guards.mjs`. This checks 85 policy, boundary, streaming, lifecycle, project and storyboard assertions. XML well-formedness was also checked. These checks cannot establish Swift compilation or runtime behavior.

`ios/Package.swift` is a separate, nongenerated pure-core XCTest harness referencing the actual NativeAccountProtocol.swift. On an authorized Mac with Swift/CryptoKit, `swift test --package-path ios` exercises endpoint/UUID/status allowlists, strict JSON preflight, resource bounds, booleans/numbers, body shape, recipient preservation, session expiry and credential/error rejection. It does not pretend to compile platform code using stubs.

**Not run here:** Swift compilation, XCTest, Xcode project build, simulator/device WebKit or URLSession tests. This environment has no Swift/Xcode/Apple SDK. No SDK installation, CocoaPods, native sync, device permission, network recipient or live-account action was attempted.

Before activation, build the real App target and run physical-device acceptance for: iframe/second-WebView/remote/file/proxy origins; root setters and persisted roots; SPA push/replace/pop history and leave/return races; reload/renderer death; scene resignation/background/disconnect; duplicate/reused/exhausted IDs; two-call saturation with prioritized clear; delayed login/session/logout against newer context/auth; same-account reauth; wall-clock changes, idle/absolute/watchdog expiry; chunked/oversized/compressed/redirect/TLS/challenge responses; cookie/cache isolation; one-shot mutation streams under transport recovery; malformed raw credentials and response-status/body mismatches; and memory/reference disposal under cancellation. Capability alone must never enable the UI.
